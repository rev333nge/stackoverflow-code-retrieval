STACKOVERFLOW CODE SEARCH — FAILURE ANALYSIS (BM25 vs dense)
===========================================================

Question: do BM25 and dense fail on the SAME queries or DIFFERENT ones?
If different, fusing them should beat either alone.


PER-QUERY NDCG@10  (val, 15,923 queries)
    BM25 mean             0.7104
    dense mean            0.7929
    oracle (best-of-both) 0.8563    (ceiling if something picked the better
                                      method on every query)
    correlation(bm,de)    0.444     (moderate — they miss different queries)

    Oracle is 0.063 above dense alone and correlation is only 0.44. That's
    real complementarity, so there's actual headroom for a hybrid.

    buckets:
        dense wins      28.1%
        BM25  wins      14.6%
        tie / both ok   53.6%
        both fail        3.7%


WHERE EACH WINS
    dense wins  - the query is worded differently from the answer's actual
                  words, and BM25 drifts to a wrong but wordy match.
                  e.g. for "Read CSV file with Python function", BM25 grabbed
                  a page about "convert a dataframe from raw text"; dense got
                  the right one.
    BM25 wins   - distinctive or exact terms, where dense drifts toward a
                  paraphrase of a different question.
                  e.g. for "groupby and convert rows into list", dense landed
                  on "How to group dataframe rows into list" - a different
                  question with a similar title.


TWO HONEST CAVEATS
1. Title echo. Queries are question titles, and documents are title+answer, so
   the query text sits inside its own answers' documents. This makes the task
   easier than free-text search and props up exact matching. See the ablation.

2. Near-duplicate label noise. Generic questions ("Transpose a DataFrame") get
   asked over and over. Both methods sometimes return a good answer from a
   different, near-duplicate question. Our qrels grade that 0, so it counts
   as a "failure" even though the result is actually useful. Some of the
   3.7% both-fail bucket is this, not an actual retrieval miss.


ABLATION — how much is the title doing?  (val, documents = answer body only)
    method               NDCG@10   MRR@10   Recall@100
    dense  title+answer   0.7929   0.8228     0.9798
    dense  answer-only    0.0614   0.0612     0.1939
    BM25   title+answer   0.7104   0.7412     0.9448
    BM25   answer-only    0.0408   0.0397     0.1269

    Both collapse without the title (~92-94% of the score gone). I expected
    dense to hold up better on answer content alone, since it's supposed to
    read meaning rather than match words - it didn't, it cratered too.

    Why: an answer body by itself is generic ("use np.flip()") and shows up
    under hundreds of similar questions. The title is what ties a generic
    answer to its specific question, for keyword matching and for meaning
    alike. Take it away and neither method can tell which labelled answer is
    the right one.

    So the title matters about equally to both methods - it's not just a
    BM25 crutch, and the title+answer comparison stays fair. Dense's real
    advantage is on the query side (handling synonyms, typos, paraphrases),
    not from reading answer content more deeply.


CONCLUSION
    BM25 and dense are complementary on the real (title+answer) system, so a
    hybrid is worth building next. Keep in mind these scores are all for the
    "title as query, find this question's answers" task, which leans on
    titles no matter the method - free-text queries would score lower across
    the board.
